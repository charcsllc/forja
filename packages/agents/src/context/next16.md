# Next.js 16 reference sheet (read this before writing framework code)

Your training data predates several of these rules. When this sheet and your memory
disagree, this sheet wins. The project's own `node_modules/next/dist/docs/` is the full
reference; read the relevant guide there with `read_file` when in doubt.

## Project facts (Forja template)
- App Router only (`src/app/**`). Pages and layouts are **server components** by default;
  add `"use client"` only to leaves that need state, effects or browser APIs.
- Development runs `next dev --webpack` (the visual editor needs the webpack hook in
  `next.config.ts`; never remove it). Production builds use Turbopack (`next build`).
- `next dev` writes to `.next/dev`; `next build` writes to `.next`. They can run at the
  same time. `output: "standalone"` is set.
- `next build` does not lint. Linting is `npm run lint` (ESLint 9 flat config);
  `next lint` no longer exists.
- Type check: `npm run typecheck` (`tsc --noEmit`). Tests: `npm test` (Vitest).
- Environment variables are read only through `src/env.ts` (zod). Never read
  `process.env` elsewhere.

## Breaking changes you must apply
- **Middleware is `src/proxy.ts`** exporting `export function proxy(request: NextRequest)`
  (plus an optional `config.matcher`). The file `middleware.ts` and the export name
  `middleware` are deprecated. `proxy` runs on the Node.js runtime; `edge` is not allowed.
- **Request APIs are async only.** `await cookies()`, `await headers()`,
  `await draftMode()`. In `page.tsx`, `layout.tsx`, `route.ts`, `default.tsx` and the
  metadata image files, `params` is a `Promise` and `searchParams` (pages) is a `Promise`:
  ```tsx
  export default async function Page(props: PageProps<"/blog/[slug]">) {
    const { slug } = await props.params;
    const query = await props.searchParams;
  }
  ```
  `PageProps`, `LayoutProps` and `RouteContext` are global type helpers generated by Next.
  In route handlers: `export async function GET(req: Request, ctx: RouteContext<"/api/items/[id]">) { const { id } = await ctx.params; }`.
- `opengraph-image`, `twitter-image`, `icon`, `apple-icon`: the image function receives
  `params` (and `id`) as promises.
- `revalidateTag(tag, profile)` needs a second argument (e.g. `"max"`). In Server Actions
  use `updateTag(tag)` for read-your-writes, `refresh()` to refresh the client router.
- Parallel route slots (`@slot`) need an explicit `default.tsx`, or the build fails.
- `next/image`: local images with query strings need `images.localPatterns`; remote hosts
  go in `images.remotePatterns` (`images.domains` is deprecated).
- React 19.2: `ref` is a regular prop (no `forwardRef` needed); `useActionState` replaces
  `useFormState`; `<form action={serverAction}>` works without JavaScript.

## Conventions that keep the build green
- Export `metadata` (or `generateMetadata`) from pages; one `<h1>` per page.
- `loading.tsx`, `error.tsx` (a client component) and `not-found.tsx` where a route
  loads data.
- Server Actions live in files starting with `"use server"`; validate input with zod.
- Import paths use the `@/` alias for `src/`.
- Never use `next/font/google` (fonts are local, under `src/app/fonts/`); never add
  third-party scripts.
